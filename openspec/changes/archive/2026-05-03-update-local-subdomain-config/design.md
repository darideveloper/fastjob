# Design: Local Subdomain Configuration

## Architectural Reasoning
The project currently relies on `localhost` and `loca.lt` (localtunnel) for development. While `localtunnel` is useful for external webhooks, it is not always needed for daily development. Standardizing on `*.localhost` allows developers to use meaningful hostnames without external dependencies.

### Configuration Strategy
We use `python-decouple` to manage settings. To enforce explicit configuration:
1. **Remove Defaults**: Remove the fallback values in `settings.py` for `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`, and `SITE_DOMAIN`. This forces the application to read these values from the environment or `.env` file, raising an error if they are missing.
2. **Template Synchronization**: Ensure `.env.example` provides clear guidance on how to configure these values.
3. **In-place Update**: Modify the active `.env` file to apply the changes immediately for the current developer.

### Affected Settings
- **`ALLOWED_HOSTS`**: Must include `fastjob.localhost` to permit the host header.
- **`CSRF_TRUSTED_ORIGINS`**: Must include `https://fastjob.localhost` to allow cross-origin POST requests (e.g., login, forms) when accessed via HTTPS.
- **`SITE_DOMAIN`**: Update to `fastjob.localhost:8000` to ensure absolute URLs generated by the app (for emails/Stripe) are correct.

## Trade-offs
- **Port Handling**: `.localhost` resolves to `127.0.0.1`, but the port still needs to be specified unless a proxy (80/443) is used. We will keep `:8000` in the defaults as it's the Django standard.
- **HTTPS vs HTTP**: CSRF trusted origins require the scheme. We will include both `http` and `https` for `fastjob.localhost` to support both direct development and proxied development.
